# Design log — PITWALL F1

## 0. Brief
- 对标：formula1.com 2026 版（深海军蓝 #15151e 顶栏 + 斜纹、暖纸色 #f7f4f1 正文底、Formula1 Display / Wide / Digits 字体、车队色半调网点车手卡、红色 #e10600 只做强调）。
- 信息架构：年份 × 赛道 × 车手 × 车队 四个基础单元（赛车挂在 车队×年份 上）。每个对象页 = 立方体的一个切片，另外三个维度可透视、可筛选；任意格子下钻到「那年那站」单场页。
- 用户追加：尽量引入 WebGL 3D 与动画转场。

**收敛决定**：B 的骨架（全幅 3D 赛道首屏 + 车手×分站矩阵）+ A 的品牌外壳（深色刊头斜纹、半调车手卡）+ C 的 77 格赛季条带；放弃时间隧道。
critic 的 5 条：12 栏网格统一首屏；用矩阵取代所有进度条；中英字体配对规则；图片纪律（照片出血、不重复抠图、历史车手不用今年照片）；WebGL 预算花在“维度切换”转场上。

## 2. 深化（critic 循环，同一份 prompt：docs/critic-prompt.md）

### Round 1 — 6.5/10（首页、车手、单场、赛车、赛道）
主要差距：① 英雄区一半空黑、3D 赛道像未打光的调试网格，赛道页照片被压暗到 15%；② Formula1 展示字体被用于 12px 数据；③ 半调车手卡与 F1.com 过于相似；④ 卡片化泛滥（历届比赛 36 张卡、逐场微卡、趣闻三卡）；⑤ 赛道页 130 行长表不折叠；⑥ 成绩表标记编码过多；⑦ 首页首屏 150px 空带、时/分/秒单位过小；⑧ 页脚红条停在 60% 像卡住的进度条。
本轮改动：见下一条记录。
（注：③ 与用户“尽可能贴近官方”的明确要求冲突，保留半调语言，但改为 WebGL 动态版本作为本站差异点。）

### Round 2 — 5.5/10（回退：上一轮改动引入缺陷）
缺陷：首页“赛道的过去”栅格错位；透视表 sticky 表头盖住数据行；赛车页模式切换被裁出边界；赛道英雄区统计换行孤立。
结构：固定高度造成大段空白；车手英雄区人像过小；“2026 技术规则”与“百科中的这一站”仍是卡片；红色承担过多含义；中英文锁定组合不统一；进站图缺少圈数网格。
本轮改动：修复全部缺陷；红色只保留给品牌、当前/下一节、主行动按钮与直播；统一“拉丁展示字 + 中文粗体”英雄锁定组合；规格改为分栏定义表；车手英雄区改为胸像裁切并让号码出血；生涯条改为连续时间轴。

### Round 3 — 6.0/10
差距：六个英雄区同一模板；3D 赛道缺标注（且“扇区色”是按三等分随意上的，并非真实扇区——需要去掉）；车队页 60 年不折叠；页面底色三种混用；“A · B × C”式标题像生成的；结果条五级灰难分辨；统计行被压在英雄区底部；胶囊标签 / 编号卡片等套路。
本轮改动：按实体类型分化英雄区（赛道＝全幅地图 + 官方标注图，单场＝成绩主导）；3D 赛道改单色 + 起终点标记，旁附官方带弯角编号的赛道图；车队年份按年代折叠；底色统一为 碳黑 + 纸色；重写全部区块标题；结果条简化为 4 级；首页矩阵上方加入“冠军形势”一句话（领先分差、剩余站数与最多可得分）。

### Round 4 — 6.0/10
最强：实时计时页（计时塔 + 车位赛道 + 赛事指令 + 无线电）被评为最接近工作室水准。
差距：首页标题 E 与积分面板相撞、赛道钻到面板下；车队车图被裁、无投影；车手头顶贴边；展示字体用于时刻与成绩时间；中英混排（“历史上的今天”换行成三行、小写 wolf、Alpine 与中文队名混用）；矩阵里未来轮次的虚线像 bug；车队英雄区斜纹、首页“年份 → 赛道 →”入口格是落地页套路。

## 用户新增需求（01:20）：解说员视角
每个单元页打开即可看到“值得说的事”（去年这里发生了什么、纪录、冷知识、故事线），并全网检索核实。实现：
- lib/talk.ts：从 F1DB 自动计算的解说要点（最近一次、胜场王、现役车手在此战绩、杆位转化率、最大逆转、退赛率、本土冠军、里程碑、队内对比、下一站战绩、首胜年龄……），全部可复现。
- content/notes.*.json：4 个研究代理全网检索并核实的故事线 / 冷知识（赛道、车手、车队、赛季）。
- 每个对象页英雄区下方的“解说要点”模块 + “本站解说手册”页（/brief）。

### Round 5 — 5.0/10（加入解说要点后）
差距：同一“解说要点”在首页 / 赛道 / 手册三处重复；标签与来源行膨胀（彩色标签、每条“F1DB 统计 · 查看”、每段 Wikipedia 下划线、01/02/03、圆点）；中英文命名不统一（表格里时中时英）；未完成状态（“历史上的今天”截断、手册“一句话”空列、车队格孤行、生涯条被截）；纸色区块没有照片。
本轮改动：解说要点卡片整卡可点、标签统一为灰色小字、来源压缩为一个“来源”；首页只放 3 条并以最近一次 / 故事线优先；车手名在表格中统一“拉丁全名为主、中文为辅”；修复所有未完成状态；赛道 / 单场的故事区放入真实照片；车队故事区加入事实侧栏。

## 3. 交付：减法清单（已删除 / 已收敛）
- 方向 C 的 WebGL 时间隧道（冠军色不可读）→ 只保留 77 格赛季条带。
- 首页“年份 / 赛道 / 车手 / 车队”四个入口卡（落地页套路）→ 删除，导航已覆盖。
- 3D 赛道上按三等分随意着色的“扇区” → 删除（不是真实扇区），改单色赛道 + 起终点线，标注交给官方赛道图。
- 积分进度条 → 改为矩阵 / 表格；对比页的双向条形图保留（那里是真对比）。
- 红色：从眉标、退赛、状态词、页脚条上撤下，只留品牌标、当前 / 下一节、主按钮、直播。
- 赛道特征胶囊标签 → 纯文本；“趣闻” 01/02/03 编号 → 删除；每段下方的 Wikipedia 长来源行 → 收成一个“来源”。
- 解说要点：彩色标签 → 统一灰色小字；每卡“F1DB 统计 · 查看 →” → 整卡可点；标题前圆点 → 删除；首页只保留 3 条。
- 车队英雄区斜纹 → 删除；sticky 表头（与容器滚动冲突）→ 删除；未来轮次虚线列 → 删除。

### Round 6 — 6.0/10 · Round 7 — 6.0/10（换了一组页面复评）
R6：首页英雄区焦点过多、解说要点模板化、赛季页人像拼贴、中英主次颠倒、手册表格被长文撑高。→ 已改：解说要点改为“主条 + 紧凑列表 + 折叠”，去重规则（同人同类 / 关键数字重合）；首页只留一个红色焦点；手册拆成“数字表 + 故事线”；中文名覆盖 226 位车手 / 38 车队 / 60 赛道（维基条目按大陆用语转换 + 人工修正港译）。
R7：赛道丝带在深色上看不清、摩纳哥高度夸张；英雄统计数字挤在一起；历史照片圆角处理与全站不一致；首页与手册要点重复；表格内小方格不可读；年代折叠占空间。

### Round 8 — 5.5/10 · 停止循环
分数曲线（critic = Fable 5.1，同一份 prompt）：发散 A5.5/B6/C4.5 → R1 6.5 → R2 5.5 → R3 6 → R4 6 → R5 5 → R6 6 → R7 6 → R8 5.5。
评审在 6 分附近稳定，剩余意见集中在两点：
1. “每类对象页同一副骨架”：这是用户指定的信息架构（四个基础单元互相透视）的直接结果。可选的下一步是给每类对象加一个专属模块（车手＝生涯曲线、车队＝历代赛车图像谱系、赛道＝带标注的大地图、单场＝逐圈名次图）。
2. 正文区图片偏少：受限于可用的授权图片（官方 CDN 只有当季车手 / 赛车 / 分站图），历史内容依赖维基图片。
最后一轮修复：手机端溢出（赛季条、历史上的今天、单场侧栏）、排位空列、图例只在需要时出现、首页去掉重复倒计时、中文锁定字号加大、纪录簿栅格按条数取列。
按 skill 规则：超过 4 轮仍 < 9 分，把分数曲线与最后一轮意见交给用户决定是否继续。

## 2026-10-09 · 互链、人物头像、月桂荣誉、历史年份中枢

用户反馈四件事，全部落地：
1. **四个基础单元处处互链**：`EntityLink`（hover 简介卡，`/api/preview/[kind]/[id]`）+ `lib/linkify.tsx`（正文中文人名 / 车队 / 赛道 / 「YYYY年XX大奖赛」/ 年份自动识别；姓氏歧义时取现役或胜场压倒性多者，如 塞纳→Ayrton、舒马赫→Michael）。
2. **人物 = 头像 + 名字**：`Person` + `/api/face/[id]`（2026 官方半身像 → 维基照片 → 车队色缩写徽章）。
3. **荣誉 = 月桂徽章**：`Laurel`（金 / 银 / 铜 / 红 / 紫 / 车队色），参照用户给的 Airbnb「房客推荐」样式。
4. **历史 = 年份中枢**：顶部导航「年份 + 赛历」合并为「历史」；左侧常驻年份栏（按规则时代分组，色块 = 车队冠军，移动端变横向条）；年份下标签 赛历 / 积分榜 / 时代 / 赛道 / 车手 / 车队，切年份保留标签。当年赛历 = 实时赛历（下一站倒计时、最新一站领奖台、逐站 ▶ 计时回放），2023 年起往年分站也可回放（`/live?year=`），更早为档案。单场页同样挂左侧年份栏。
另：3D 赛道高度改为每条赛道自适应放大（`components/three/relief.ts`），平坦街道赛也能看出起伏，并标注真实落差与倍数。
