# 解说要点内容

2026-10-12：首批增加21条核实内容，覆盖场外故事、人物关系、职业动向、涂装、技术与周末前瞻。原卡片继续全部展开。

- `content/notes.editorial.json` 保存可关联多个对象的事实，每条只写一次；`related` 指明车手、车队、赛道、赛季或分站。
- `content/notes.races.json` 是独立分站入口，以 `年份/站次` 为键。可通过 `notes.race(year, round)` 获取；关联赛道时仍复用同一条事实。
- `topic` 是具体事实的稳定标识。优先按标识去重，明确不同话题不会只因数字相同而互相覆盖。brief也在各模块之间去重。
- `year` 表示事件年，不把过去的人物故事改成2026新闻。`eventDate`、`publishedAt`、`verifiedAt`分别标明事件、发布和核实日期；没有准确日期时留空。
- `preview` 绑定目标分站并带有效期，正赛结果入库后停止当前前瞻；`snapshot`记录明确截止时点，短期职业动向也可以设有效期。静态旧成绩稿已标为截至2026第16站的历史观察；31条过时的实时算术稿改由数据库解说承担。
- 新加坡限定涂装只关联新加坡，不能成为美国站的新涂装。当前仅提供文字与官方图集链接。
- `racePreview`使用目标站之前的积分与成绩，计算冠军形势、近期状态、赛制和赛道历史。历史分站显示“赛前档案”，不会读取后续成绩。当前现代积分数学采用全额正赛25分、冲刺8分，不依赖同分规则宣称冠军已经确定；旧积分规则不作这种推算。
- 数据库切换到新的已核实版本时，解说缓存立即失效。中文新闻仍需核实、编辑和发布，数据库更新不会自动抓取新闻。

来源、日期和公开表态标识保留在卡片与复制稿。发布前运行 `npm test`、`npm run validate` 和 `npm run build`；校验涵盖关联实体、分站、日期、有效期、唯一话题标识和来源。
